# ⚽ MatchMind — Agentic Match Intelligence Studio

**Inside the Game: Developer Hackathon (Microsoft × Premier League) submission.**

MatchMind turns a live stream of synthetic football events into explainable
match intelligence: real-time stats, tactical explanations, multi-language
narration and personalized viewing experiences — plus a player **Load & Risk
Monitor** grounded in sports science (ACWR).

> **Synthetic data only.** Every club, player, event and statistic in this
> project is fictional and generated by our own simulation engine. No real
> Premier League data is used. The eight clubs of the MatchMind Synthetic
> League echo the archetypes of English football (colours, regions, playing
> styles) but their names, kits and crests are invented; no real club name,
> nickname, badge motif or trademark appears anywhere.

## The five-stage pipeline

| Stage | Component | Status |
|---|---|---|
| 1. Ingest | Synthetic match engine + FastAPI/WebSocket live replay (configurable speed) | ✅ |
| 2. Interpret | Interpreter agent: team stats, xG race, momentum, per-player ACWR workload | ✅ |
| 3. Explain | Analyst agent (gpt-4o, Agent Framework): *why* a moment matters, grounded in the Interpreter's numbers, plus a 10-minute forecast that the Judge grades | ✅ |
| 4. Render | Narrator agent (English analytical, casual, play-by-play, *relator rioplatense* 🇦🇷) + live 2D pitch & overlays (React) | ✅ agent / 🔜 UI |
| 5. Personalize | Director agent: decides per viewer (Analyst / Casual / Commentator / Player-Focus, language) which cards to show and how loudly | ✅ |

## Architecture (target)

- **Azure AI Foundry** — model hosting (gpt-4o / gpt-4.1-mini) + evals
- **Microsoft Agent Framework** — multi-agent orchestration (Interpreter,
  Analyst, Narrator, Director, Load & Risk Monitor)
- **MCP server** — match-state tools exposed to agents
- **Azure Container Apps** (backend) + **Azure Static Web Apps** (frontend)
- Built with **GitHub Copilot** assistance

## Quickstart

```bash
cd backend
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m matchmind.generate_match --home THU --away NBF --seed 42 --out ../data
.venv/Scripts/python -m pytest
.venv/Scripts/python -m uvicorn matchmind.api.app:app --port 8000
```

The simulator outputs an event stream (`*_events.jsonl`) and match metadata
(`*_meta.json`). The streamer replays any match in `data/` as a live feed:

- `GET /matches` — catalogue, `GET /matches/{id}/meta` — teams, squads, 28-day load history
- `WS /ws/matches/{id}?speed=10&mode=commentator&lang=es&player=THU-15` — every
  event in match-clock order (speed 1 = real time, 0 = instant); send
  `{"speed": 50}` or `{"profile": {...}}` to change speed / viewer profile live.
  Key events carry an Interpreter snapshot (score, team stats, xG race, momentum,
  per-player workload with live ACWR and risk alerts) and, a few seconds later,
  an `insight` message with the Analyst explanation, the Narrator line and the
  Director decision for that viewer.
- `POST /matches/{id}/branches` — **what-if**: re-simulate the match from a
  minute with a substitution or a tactical change. Same seed, so the branch is
  identical to the real match until that minute and diverges after; the
  response compares both timelines (score, xG, shots, injury concerns).
- `POST /mcp` — MCP server (streamable HTTP) exposing `list_matches`,
  `get_match_state`, `get_player_workload`, `get_risk_alerts`, `get_xg_race`,
  `get_risk_windows`, `get_analyst_credibility`, `simulate_intervention` to any
  MCP client. The same functions are the agents' tools.

## AI that gets graded, not just heard

The **Load & Risk Monitor** predicts injury-risk windows per player from
observable workload only (live ACWR, minutes, sprint density, previous knocks,
metres-per-minute drop against the position norm). Because the simulator's
hidden fatigue produces observable `injury_concern` events, every prediction is
scored live: precision, recall, lead time, and where the player ranked among
everybody on the pitch when the knock happened. A naive baseline (risk = minutes
played) runs alongside with the same window policy (top 5 hazards on the
pitch), so the scorecard shows whether the model adds anything.

Offline evaluation over 40 simulated matches (`python -m matchmind.risk.evaluate --matches 40`):

| | Risk Monitor | Minutes-only baseline | Random pick |
|---|---|---|---|
| Knock happened to a top-3 hazard player | 32% | 16% | 14% |
| Knocks covered by an open window | 46% | 26% | |
| Mean warning time | 25 min | 18 min | |
| Windows that came true | 9% | 8% | |
| Alerts per match | 14 | 8 | |

Honest reading: the monitor ranks risk far better than chance or a minutes
heuristic, but most windows still pass without a knock. That is what the
scorecard is for.

**Ground truth, stated openly.** The simulator's per-minute knock hazard is
convex in latent fatigue, spikes when the pre-match ACWR exceeds 1.3, and is
scaled by a latent individual susceptibility (0.5-1.0). The monitor never sees
fatigue or susceptibility; it only sees what leaks into the observables. The
knock model draws from its own random stream, so changing it never changes a
pass or a shot.

The **Coach agent** turns high-risk alerts into proposals, and the engine shows
the counterfactual branch of each proposal.

The **Analyst is graded too.** Every read ends with a forecast for the next 10
match minutes: which side creates more xG, the probability of a goal, and the
player most likely to be involved. The forecast goes into a ledger; when its
window closes, code settles each claim (dominance by xG created, the goal call
by a Brier score, the watched player by involvement in a shot, goal or knock)
and the **Judge agent** writes the verdict and the lesson in the viewer's
language. A naive forecast making the same three claims (the xG leader keeps
dominating, base-rate goal odds, the top shooter so far) is graded on the same
windows, so the Analyst's running credibility is
always shown next to a baseline, on the Analyst seat and in the Control room,
and is exposed to agents and MCP clients as `get_analyst_credibility`. Windows
close on the exact minute mark even when an insight arrives late at replay
speed, and nothing is forecast once the final whistle has gone.

## Agents

| Agent | Model | Job |
|---|---|---|
| Interpreter | none (pure Python) | Stats, xG race, momentum, ACWR workload per player |
| Analyst | gpt-4o | Explains why a key moment matters (structured output) |
| Narrator | gpt-4.1-mini | One commentary line per viewer profile and language |
| Director | gpt-4.1-mini | Picks the cards and priority each viewer gets |
| Load & Risk Monitor | none (pure Python) | Predicts risk windows from observables; self-evaluates against ground truth |
| Coach | gpt-4o | Proposes substitutions / tactical changes on risk alerts; the engine simulates the branch |
| Judge | gpt-4.1-mini | Reads each settled forecast (scores come from code) and writes the verdict and the lesson |

All agents run on **Azure AI Foundry** through the **Microsoft Agent Framework**
(Python). A deterministic key-moment gate decides when they wake up, so cost and
latency stay predictable (~3-6 s per moment). Try them from the CLI:

```bash
.venv/Scripts/python -m matchmind.agents.demo --limit 3 --mode analyst --mode commentator:es --mode player_focus:en:THU-15
```

## Who would use this

- **Performance and medical staff**: the Risk Monitor turns the workload they
  already track (GPS distance, sprints, 28-day load, ACWR) into warnings with
  a lead time, and keeps an honest scorecard of how often it was right. Nothing
  in the method depends on the data being synthetic.
- **The coaching bench**: the Coach agent proposes a substitution or a tactical
  change on a high-risk window, and the engine shows the counterfactual before
  the decision is made.
- **Broadcasters and fans**: the same match personalised by seat and language,
  with every agent decision traceable in the Control room.

## Orchestration

Key moments run as a Microsoft Agent Framework workflow: `ConcurrentBuilder`
fans the moment out to the Analyst and the Narrator, the Director takes their
structured outputs. Middleware records every agent run and tool call into a
trace that the Control room seat renders as swimlanes. If the workflow fails,
the moment is served through direct calls and the trace says so.

## Responsible AI note

The Load & Risk Monitor is **decision support, not medical advice**. It flags
workload patterns (acute:chronic workload ratio, sprint density, fatigue
proxies) on synthetic athletes for illustrative purposes only.
